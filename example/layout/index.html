窗口正文里怎么排

五张卡片 = graphcalc / miko 示例里真实存在的五种正文(每张都写出处). 顶上切两档:现状照抄它们今天自己写的那几行 CSS,方案换成库的两个原语 createStack / createScrollArea.右边挂着窗口高度滑杆, 每张卡片下面的数字是现场量的.

现在真正缺的是什么(从这五张卡片里读出来)
  1. 分组那一半库已经有了:graphcalc 的视图设置 = 一个滚动容器 + N 个 createControlGroup 分组,每行固定高.分组件是库的,不用再造.
  2. 缺的是容器那一半:"一个吃掉剩余高度,超出就滚的区" + "里面按顺序摞,间距统一". 今天这两件事消费者要各写一遍:graphcalc 的 #view-controls(8 行 CSS),#params-panel(6 行 + 1 个 :root 令牌),.object-list-body(5 行 + 4 层包裹), 站点面板正文再写一遍(margin 节奏).
  3. 滚动条要手挂:库的 .ui-scrollbar 是单独一条规定,组件不认识它 -- graphcalc 手挂了 14 处,站点漏挂 2 处.滚动容器归库之后,这件事就该由库做.
  4. 示例的读数窗口只能用"垂直居中"凑(example.css 的 .pane { justify-content: center }):因为没有"从上往下摞"的出口. 见第 ⑤ 张卡片.
滚动区(吃掉剩余,超出就滚) .control-group:库已有的分组件 红= 这一档有问题(滚不动 / 行被压 / 越界被裁)

方案:库给两个原语(其余不动)

/* createStack:按顺序堆叠 + 统一间距/内边距 */
createStack({
    gap: '8px',
    padding: '8px',
    children: [ group1, group2, group3 ],
})

/* createScrollArea:吃掉剩余 + 滚 + 可选下限 + 自带 .ui-scrollbar */
createScrollArea({ minHeight: '120px', child: stack })

这次不做的东西(没有消费者)

× "工具条 + 主体 + 底栏" 三明治
    graphcalc 六个窗口正文全是**单子节点**,
    没有这种布局.方案初稿拿它当 Phase 4
    的理由,是凭空造的 -- 演示里已删.

× Splitter 分栏
    graphcalc 窗口化时把自己的分栏控制器
    删了(RightSplitController / #right-splitter).

× 表格件 / 折叠面板 / 搜索框
    分组已经有 createControlGroup,
    再往上没有真实需求.

√ 只做:createStack(顺序堆叠)
      + createScrollArea(吃剩余 + 滚)
  理由就是左边那几段 CSS 的重复部分.
